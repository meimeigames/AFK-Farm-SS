# AFK Farm — помощник фарма для MMORPG «Седьмой элемент»

Отдельное Windows-приложение с графическим интерфейсом, которое само ищет монстров,
атакует их, использует умения, пьёт зелья HP/MP и перемещается по локации.

Программа работает **только снаружи игры**: делает снимки окна, распознаёт полосы
на изображении и нажимает клавиши/кликает мышью через стандартный `SendInput`.
Никаких DLL-инъекций, чтения или изменения памяти, вмешательства в клиент
и обхода античита.

> ⚠️ Автоматизация может противоречить правилам игры. Используйте на свой риск.

## Режим по умолчанию (простой)

Программа сразу настроена так:

| Ситуация | Что нажимается |
|---|---|
| полосы HP моба нет | **TAB** (каждые 0,6 с), пока полоса не появится |
| полоса HP моба есть | **F** без остановки (каждые 0,3 с), пока полоса не пропадёт |
| во время боя | цифры **1–8** периодически (каждая раз в 5 с) |
| HP персонажа < 50% | **0** (зелье HP) |
| MP персонажа < 50% | **9** (зелье MP) |

Бот в этом режиме не ищет монстров по карте и не ходит. Для работы нужно откалибровать
**«Полосу HP цели»** (и полосы HP/MP персонажа — для зелий) на вкладке «Калибровка».
Все клавиши, интервалы и пороги меняются на вкладках «Бой» и «Зелья». Полный режим с поиском,
застреванием и маршрутами включается на вкладке «Бой» → «Режим».

## Бот видит HP/MP, но в игре ничего не нажимается

Почти всегда причина одна: **игра запущена от имени администратора, а программа — нет.** Windows
(механизм UIPI) молча отбрасывает эмулированные нажатия из обычной программы в окно администратора,
при этом снимок экрана работает — поэтому HP и MP видны.

- Программа сама это определяет: на «Главной» появляется красное предупреждение и кнопка
  **«Перезапустить от имени администратора»**. Можно также запускать через `run_admin.bat`
  или ПКМ по `AFKFarm.exe` → «Запуск от имени администратора».
- Кнопка **«Проверить ввод»** на «Главной» активирует окно игры и один раз нажимает клавишу выбора цели:
  если монстр выделился — ввод доходит. Результат и права программы/игры пишутся в журнал.
- Если права одинаковые, а нажатия всё равно не доходят: «Настройки» → «Способ ввода» →
  «Виртуальные коды», затем «Удержание клавиши» 0.15 с. Если не помогло ничего — клиент игры,
  вероятно, игнорирует эмулированный ввод; обходить такую защиту программа не будет.

## Возможности

- Поиск ближайшей цели (**TAB**), проверка, что цель действительно выбрана (по рамке цели), атака (**F**).
- Ротация боевых умений: своя клавиша, перезарядка, время каста, минимальный MP, условие по HP цели, приоритет.
- Баффы по таймеру (вне боя или в бою).
- Распознавание **HP и MP персонажа** и **HP цели** по цвету и заполнению полос.
- Зелья HP/MP с порогами, перезарядками, минимальной паузой, критическим порогом и доп. клавишей;
  опциональная проверка перезарядки по затемнению слота; предупреждение, если зелья «не действуют».
- Распознавание смерти цели → сразу **TAB** к следующей; сброс «застрявшей» цели (HP не уменьшается).
- Перемещение: маршрут из точек (запись кликами прямо в игре или щелчками по снимку), случайное блуждание,
  определение прибытия по мини-карте, поиск целей во время движения.
- Отдых вне боя (если в игре есть клавиша отдыха).
- Глобальные горячие клавиши: **F10** старт, **F11** пауза, **F12** аварийная остановка, **F8** точка маршрута.
- Режим калибровки: снимок окна, выделение областей мышью (с масштабом), **автопоиск** полос HP/MP,
  полосы цели и мини-карты, запоминание цветов, живой тест распознавания.
- Все настройки меняются **на лету** во время работы и сохраняются в `config.json`.
- Журнал в окне и в файле `logs/afkfarm.log` (с ротацией).

## Что распознаётся на экране

Интерфейс проанализирован по скриншоту (1280×800) и видеозаписям боя:

| Элемент | Где | Как распознаётся | Автопоиск |
|---|---|---|---|
| HP персонажа | внизу слева, красная полоса `12359/12359` | доля «красных» столбцов пикселей | ✅ |
| MP (ОМ) | под HP, синяя полоса | то же, синий цвет | ✅ |
| Цель выбрана / HP цели | вверху по центру: портрет, имя, красная полоса с `%` | полоса цели есть и заполнена > 0 | ✅ (при выбранной цели) |
| Движение персонажа | мини-карта внизу справа | изменение картинки за 0,3 с | ✅ |
| Перезарядка зелья | иконка на панели быстрого доступа | затемнение относительно эталона | — (выделить вручную) |
| Точка персонажа | центр экрана, ноги персонажа | задаётся щелчком | — |

**Почему распознавание устойчиво к цифрам на полосе.** Для каждого столбца пикселей считается доля пикселей
нужного цвета. Белые цифры `37603/43503` закрывают только середину столбца — цветные пиксели сверху и снизу
остаются, и столбец всё равно считается заполненным. Затем берётся длина непрерывной заливки от левого края.

**Защита от ложных показаний.** Для каждой полосы вычисляется достоверность — насколько маска похожа на
«заполнено слева, пусто справа». Дополнительно пустая часть настоящей полосы — тёмный трек: если там светло,
полосу перекрыло окно/подсказка, и показание считается **ошибкой распознавания**, а не «0% HP».
Значения HP/MP сглаживаются медианой по последним кадрам.

Проверка на реальных кадрах (`tests/test_vision.py`):

| Кадр | Факт | Распознано |
|---|---|---|
| скриншот, HP 12359/12359 | 100% | 100% |
| скриншот, MP 4806/4929 | 97,5% | ≈98% |
| видео, HP 37603/43503 | 86,4% | ≈88% |
| видео, MP 12812/13366 | 95,9% | ≈98% |
| видео, HP цели «Курама» | 73% | ≈75% |

Погрешность 1–3% — следствие сжатия видео; для порогов зелий этого более чем достаточно.

## Архитектура

```
main.py                     запуск приложения
afkfarm/
├─ config.py                настройки (dataclass) ↔ config.json, потокобезопасный ConfigStore
├─ logger.py                журнал: файл с ротацией + вывод в интерфейс, защита от спама сообщений
├─ keys.py                  таблица клавиш (VK + скан-коды), разбор сочетаний CTRL+1
├─ winapi.py                ctypes: окна, курсор, SendInput, GetAsyncKeyState
├─ clock.py                 часы с прерываемым ожиданием (и виртуальные — для тестов)
├─ game_capture.py          поиск окна игры, захват клиентской области (MSS)
├─ vision.py                распознавание HP/MP/цели, автопоиск областей, мини-карта, слоты
├─ game_control.py          клавиатура/мышь + InputGuard (лимиты нажатий, отпускание клавиш)
├─ potions.py               логика зелий
├─ combat.py                ротация умений, баффы, прогресс по цели
├─ movement.py              маршрут, случайное блуждание, запись маршрута, прибытие
├─ bot.py                   главный цикл и конечный автомат режимов (отдельный поток)
├─ hotkeys.py               глобальные горячие клавиши
└─ ui/                      интерфейс PySide6
   ├─ main_window.py        главное окно, связывание всего, сторожевой таймер
   ├─ dashboard.py          «Главная»: Старт/Пауза/Стоп, HP/MP/цель, статистика, журнал, превью
   ├─ tabs.py               «Бой», «Зелья», «Настройки», таблица умений/баффов
   ├─ route_tab.py          «Маршрут»
   ├─ calibration_tab.py    «Калибровка»
   ├─ canvas.py             холст снимка: выделение областей, точки, масштаб
   ├─ widgets.py            поле ввода клавиши, привязка виджетов к настройкам, журнал
   └─ style.py              тёмная тема
tests/                      тесты распознавания, симуляция игры, тесты интерфейса
```

Предложенная в задании структура (`interface.py`, `combat.py`, …) сохранена, но расширена:
логика режимов вынесена в `bot.py` (чтобы бой, зелья и перемещение не зависели друг от друга),
интерфейс разбит на несколько файлов, а работа с WinAPI и клавишами — в отдельные модули.
Бот не зависит от Qt и полностью тестируется на симуляции игры.

**Потоки.** Интерфейс — главный поток. Бот — отдельный поток: он читает актуальный снимок настроек на
каждом такте и передаёт статус в интерфейс через сигналы Qt. Горячие клавиши — третий поток (опрос
`GetAsyncKeyState` каждые 30 мс), аварийная остановка срабатывает прямо из него.

**Режимы бота:**

```
          ┌──────────── цель найдена во время движения ─────────────┐
          ▼                                                          │
 ПОИСК ──TAB, рамка цели появилась──► АТАКА ──цель исчезла──► (ЛУТ) ─┤
   │  ▲                                 │                           │
   │  └──── HP цели не меняется / ──────┘                           │
   │        слишком долгий бой (ESC)                                │
   │                                                                │
   ├── N неудачных TAB ──► ПЕРЕМЕЩЕНИЕ ──прибыли──► ПОИСК           │
   └── мало HP/MP (если включено) ──► ОТДЫХ ──восстановились──► ПОИСК
 Зелья проверяются на каждом такте в любом режиме (наивысший приоритет).
```

## Установка

Нужны **Windows 10/11** и **Python 3.10+ (64-bit)** — https://www.python.org/downloads/
(при установке отметьте «Add python.exe to PATH»).

1. Скачайте проект (кнопка Code → Download ZIP) и распакуйте, например, в `C:\AFKFarm`.
2. Запустите **`install.bat`** — создаст окружение `.venv` и установит зависимости.
3. Запускайте **`run.bat`** (или `run_debug.bat` — с консолью, если нужно увидеть ошибки).
   Если игра запущена от имени администратора — **`run_admin.bat`**.

Вручную:

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Зависимости: `PySide6` (интерфейс), `opencv-python` + `numpy` (зрение), `mss` (захват экрана).
Клавиатура и мышь — через WinAPI `SendInput` (ctypes), без сторонних библиотек: в отличие от
PyAutoGUI/pynput, программа отправляет **скан-коды**, которые надёжно принимают DirectX-игры.

## Первый запуск: пошаговая настройка

1. **Игра в оконном режиме** или «окно без рамки». Полноэкранный DirectX-режим часто даёт чёрный снимок.
   Не меняйте размер окна после калибровки (если меняли — откалибруйте заново).
2. **Настройки → Заголовок окна → «Выбрать…»** — укажите окно игры. Вверху «Главной» должно появиться
   «Окно игры: … — 1280×800».
3. **Калибровка**:
   1. «📷 Снимок окна игры» (программа на секунду свернётся, чтобы не перекрывать игру).
   2. При полных HP и MP — «Найти полосы HP и MP». Проверьте рамки на снимке; при необходимости поправьте
      поля X/Y/Ш/В или обведите полосу мышью (колесо — масштаб, ПКМ — сдвиг).
   3. Выберите монстра в игре (TAB) **с полным HP**, сделайте снимок ещё раз, нажмите «Найти полосу HP цели».
      Без полосы цели бот работает в «слепом» режиме (TAB + атака по таймеру) — менее надёжно.
   4. «Найти мини-карту» (или обведите вручную) — нужна, чтобы понимать, что персонаж остановился.
   5. Выберите «Персонаж (точка)» и щёлкните по ногам персонажа.
   6. «Проверить на снимке» / «▶ Живой тест»: должны показываться верные проценты.
      Если цвета «плывут» — «Запомнить цвета HP/MP (при 100%)».
4. **Бой**: TAB/F уже заданы. Добавьте умения: клавиша (щёлкните в поле и нажмите клавишу или
   сочетание), перезарядка, время каста, минимальный MP. Порядок строк — приоритет.
5. **Зелья**: по умолчанию `0` при HP < 50% и `9` при MP < 50%; при необходимости поменяйте клавиши, пороги и перезарядки.
6. **Маршрут**: выберите режим. Для маршрута — «⏺ Запись кликами в игре» и пройдите кругом по месту фарма,
   щёлкая по земле; или щёлкайте по снимку на этой вкладке.
7. **Главная → Старт** (или F10). Бот активирует окно игры и через 2 с начнёт работу.
   **F12** — аварийная остановка в любой момент, **F11** — пауза.

## Как работает цикл фарма

На каждом такте (по умолчанию 50 мс):

1. Снимок окна → HP, MP, наличие и HP цели, движение мини-карты.
2. Проверки: окно игры активно? HP распознаётся? персонаж жив? нет ли спама клавиш?
3. **Зелья** (если HP/MP ниже порогов и зелье не на перезарядке).
4. Режим **ПОИСК**: баффы (если пора) → TAB → ждём рамку цели `target_confirm_delay`.
   Цель появилась → **АТАКА** (F). Нет → повтор через `search_delay`; после `max_search_attempts`
   неудач → **ПЕРЕМЕЩЕНИЕ**.
5. Режим **АТАКА**: умения по приоритету с учётом перезарядки и `action_delay`; если умения не готовы —
   повтор F раз в `attack_repeat_interval`. Цель исчезла → «убита» → сразу TAB к следующей.
   HP цели не уменьшается `stuck_timeout` секунд или бой дольше `max_fight_time` → ESC и новая цель;
   несколько таких подряд → смена места.

Каждый обработчик делает **не больше одного действия за такт** и никогда не ждёт бесконечно —
все ожидания реализованы через отметки времени.

## Зелья

- HP < `Пить, если HP ниже` → зелье HP, если прошла его перезарядка.
- HP < `Критический порог` → сначала доп. клавиша (сильное зелье / умение лечения, если задана), а
  готовность обычного зелья при включённой визуальной проверке перепроверяется чаще таймера.
- MP < порога → зелье MP.
- Между любыми зельями — `Мин. пауза` (по умолчанию 1 с). Перезарядка каждого зелья — свой таймер.
- **Визуальная проверка перезарядки** (необязательно): выделите иконки зелий на «Калибровке», при готовых
  зельях нажмите «Запомнить слоты зелий», включите флажок на «Зельях». Пока слот затемнён — не нажимается.
- Если зелье N раз подряд не подняло HP/MP — в журнале предупреждение (кончились зелья / неверная клавиша).
- При HP = 0 дольше `death_confirm_time` бот останавливается (или ставится на паузу — настраивается).

## Перемещение и маршрут

В игре персонаж ходит кликом ЛКМ по земле, поэтому точка маршрута — это **место клика в окне игры**.

- **Маршрут по точкам** — по кругу (1→2→3→1) или туда-обратно. У точки можно задать паузу после прибытия.
  Запись: «⏺ Запись кликами в игре» (каждый щелчок ЛКМ по окну игры добавляет точку), «＋ Точка под
  курсором» / **F8**, или щелчок по снимку на вкладке «Маршрут». «Проверить выбранную точку» — кликнет в игре.
- **Случайное блуждание** — клик на случайном расстоянии от персонажа с плавной сменой направления,
  только внутри «безопасной зоны» (без интерфейса по краям).
- **Стоять на месте** — только ждать появления монстров.
- **Прибытие** определяется по мини-карте: пока персонаж идёт, она меняется; неподвижна `stable_time` →
  пришли. Без мини-карты — ожидание `max_travel_time`.
- Во время движения бот периодически жмёт TAB: если монстр выбран — сразу атакует.

⚠️ Точки задаются относительно экрана, поэтому **не поворачивайте камеру во время фарма**: при неподвижной
камере замкнутый маршрут (сумма шагов ≈ 0) раз за разом обходит одно и то же место.

## Надёжность и защита

| Механизм | Что делает |
|---|---|
| Аварийная остановка F12 | срабатывает из отдельного потока, мгновенно; все клавиши отпускаются |
| Проверка активного окна | нет фокуса на игре → ни одного нажатия (режим «Ожидание окна игры») |
| InputGuard | лимит нажатий одной клавиши и всех действий за 10 с; мин. пауза между нажатиями; при массовой блокировке — пауза бота |
| Перезарядки/задержки | у каждого умения, баффа, зелья — свой таймер; мин. перезарядка 0,3 с даже при 0 |
| Гарантированное отпускание | каждая нажатая клавиша отпускается в `finally`; при паузе/остановке — `release_all` |
| Ошибки распознавания | недостоверное показание не превращается в «0%»; N кадров подряд без HP → пауза |
| Смерть персонажа | HP = 0 дольше N с → остановка или пауза |
| Застрявшая цель | HP цели не меняется → ESC, новая цель; несколько раз подряд → смена места |
| Сторожевой таймер | цикл бота не отвечает дольше `watchdog_timeout` → аварийная остановка |
| Исключения | ошибка в такте логируется, клавиши отпускаются, 10 ошибок подряд → остановка |
| Журнал | `logs/afkfarm.log` с ротацией (5 × 2 МБ), повторяющиеся сообщения не спамят |
| Настройки на лету | изменения применяются сразу, без перезапуска; файл пишется атомарно |

## Значения по умолчанию и что нужно уточнить

Некоторые данные зависят от вашего персонажа и клиента — проверьте их:

| Что | По умолчанию | Почему важно |
|---|---|---|
| Заголовок окна игры | `7th Element\|Седьмой элемент\|Element` | точное название окна клиента неизвестно — выберите через «Выбрать…» |
| Клавиши зелий HP/MP | `0` при HP < 50% / `9` при MP < 50% | как вы просили; перезарядки зелий уточните |
| Перезарядка зелий | 10 с | у разных зелий в игре своя перезарядка |
| Умения | `1`–`8`, каждое раз в 5 с | перезарядку каждого умения можно выставить точно |
| Слоты «C-1…C-0» на панели | — | предположительно CTRL+цифра; в поле клавиши нажмите нужное сочетание |
| Клавиша подбора лута | не задана | если в игре нет автоподбора — укажите клавишу |
| Клавиша отдыха | не задана | если есть «сесть/медитация» — можно включить отдых |
| Пороги HP/MP | 70% / 30%, критический 40% | под ваш класс и зелья |
| Области интерфейса | для 1280×800 | для другого размера окна запустите автопоиск |

## Сборка .exe

**Готовая сборка без установки Python.** При каждом push GitHub Actions на Windows прогоняет все тесты
(включая интеграционные: поиск окна, захват экрана, ввод через SendInput) и собирает программу.
Откройте вкладку **Actions** репозитория → последний успешный прогон «Windows — тесты и сборка» →
внизу артефакт **AFKFarm-windows** (zip). Распакуйте и запустите `AFKFarm.exe`.

Собрать самостоятельно:

```bat
build_exe.bat
```

Результат — папка `dist\AFKFarm\` с `AFKFarm.exe` (PyInstaller, режим «папка»: быстрее стартует и реже
вызывает ложные срабатывания антивирусов, чем один файл). Папку можно переносить целиком; `config.json`,
`logs\`, `routes\` создаются рядом с exe.

## Решение проблем

| Симптом | Решение |
|---|---|
| Снимок чёрный | Оконный режим или «окно без рамки» вместо полноэкранного |
| Окно игры «не найдено» | «Настройки → Выбрать…»; игра не должна быть свёрнута |
| Клавиши не доходят до игры | См. раздел «[Бот видит HP/MP, но в игре ничего не нажимается](#бот-видит-hpmp-но-в-игре-ничего-не-нажимается)» |
| HP «не распознано» | Перекалибруйте полосу HP; «Запомнить цвета HP/MP (при 100%)»; уберите окна, перекрывающие полосу |
| Цель не определяется | Откалибруйте «Полосу HP цели» при выбранном монстре; проверьте «Живой тест» |
| Персонаж не останавливается по мини-карте | Увеличьте «Порог движения мини-карты» (там бывают мигающие значки) |
| «Защита от спама» ставит паузу | Увеличьте перезарядки умений / `action_delay` или лимиты на вкладке «Настройки» |
| Бот кликает по интерфейсу | Увеличьте отступы безопасной зоны на вкладке «Маршрут» |
